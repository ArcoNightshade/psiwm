# iwm: OpenBSD to illumos port notes

Sources: OpenBSD `sys/dev/pci/if_iwm.c` v1.419, `if_iwmreg.h` v1.70, `if_iwmvar.h` v1.79,
`sys/net80211/ieee80211_ra.c` v1.5, `ieee80211_amrr.c` v1.12. Code outside the items below
follows OpenBSD line for line, so upstream fixes can be carried over by diff.

## Files
| File | Content |
|---|---|
| `if_iwm.c` | The driver (OpenBSD if_iwm.c) plus illumos attach/detach, GLDv3 entry points |
| `if_iwm_proto.h` | Prototypes of its static functions; generated by `docs/tests/genproto.py` |
| `if_iwmreg.h` | OpenBSD if_iwmreg.h verbatim (CSTYLED block) |
| `if_iwmvar.h` | Softc, rings, node; illumos types replace bus_dma/mbuf/task |
| `if_iwmcompat.h` | Mechanical shims (byte order, `nitems`, `DELAY`, EDCA names) |
| `if_iwm_ra.[ch]`, `if_iwm_amrr.c` | MiRA and AMRR (illumos net80211 has neither) |

## Mapping of OpenBSD mechanisms
- `splnet()` -> `sc_mtx`, held across the whole control path; `tsleep_nsec()` ->
  `iwm_sleep()` (cv_reltimedwait on `sc_fw_cv`/`sc_txq_cv`), command waits on `sc_cmd_cv`
  with a per-slot `sc_cmd_done[]` flag. `ioctl_rwl` -> `sc_rwlock` (init/stop/restart).
- `task_add` -> `iwm_add_task()`: one bit per task, two single-threaded taskqs (init; newstate,
  BA, MAC context, deferred net80211 work). `task_refs` -> `sc_task_refs`; init_task is not
  counted, as in OpenBSD, so iwm_stop() can wait for the others.
- mbufs: Rx buffers stay on the ring and frames are copied into mblks; Tx payload is copied
  into per-slot DMA buffers (2 KB, two per page; command queue one page per slot). Tx buffers
  are allocated at attach for the command, four EDCA and eight aggregation queues (~7 MB).
- Work that calls into net80211 from the interrupt in OpenBSD (end of scan, beacon miss, BAR,
  frame input, Tx restart) is queued and run after `sc_mtx` is dropped: frame input and
  `mac_tx_update()` at the end of `iwm_intr()`, the rest from `iwm_defer_task()`.
- `if_watchdog` -> `ddi_periodic` 1 s per-queue Tx timers; net80211's own watchdog drives
  auth/assoc timeouts through `ic_watchdog`.
- `ic_ampdu_rx_start/stop`, `ic_ampdu_tx_start/stop` -> illumos `ic_recv_action`,
  `ic_addba_response`, `ic_addba_stop` hooks (net80211 does the ADDBA exchange and Rx
  reordering; the driver programs the firmware from the BA task).
- `ic_set_key` -> `cs_key_set`: pairwise CCMP in hardware, everything else marked
  `IEEE80211_KEY_SWCRYPT`. net80211's `ccmp_encap` writes the IV; firmware adds the MIC.
- HT MCS set given to net80211 by `ieee80211_attach_mcs()` (MCS 0-7 or 0-15 by antennas).
- Firmware is read with `firmware_open()` from `/kernel/firmware/iwm` at attach (the INIT
  image must run then: MAC address and channels are needed before mac_register()).
- Scans and connections are started by net80211 ioctls (dladm), not by `iwm_init()`.

## Deliberate deviations
- No monitor mode, MFP, background scan, VHT, MSI-X, 7000/9000 paths, MQ Rx.
- `iwm_ra_get_ht_rateset()` returns the SISO set instead of panicking on a bad MCS.
- Unhandled firmware notifications are logged only with `IWM_DEBUG`.
- Firmware error log is always written to the system log (OpenBSD: only with IFF_DEBUG).
- `iwm_rx_pkt()` validates notification payload lengths before use (OpenBSD trusts them),
  including the PHY DB section length.
- Tx QoS frames use the queue of their access category (OpenBSD sends all on BE).

- Rx BlockAck sessions are tracked per TID (`sc_rx_ba_tidmask`), not only counted.
- Counted tasks clear their pending bit on entry so requests made while they run are kept.
- Deferred end-of-scan runs only in SCAN state; leaving SCAN early aborts the firmware scan.
- Data frames are dropped (not flow-controlled) on allocb failure or during a Tx flush;
  `mac_tx_update()` is sent after stop and on entering RUN.
- The newstate task does nothing while the device is down (RF-kill at plumb, or stopped).
- Detach and attach failure tear the interrupt down before net80211 and the MAC handle.

## Upstream bugs found and fixed
- `iwm_nvm_read_chunk()` forced the read offset to 0 (see audit notes).
- Firmware TLV parse: signed API/capability index (out-of-bounds bit write on a bad
  image), CMD_VERSIONS shrinking tlv_len and desynchronising the TLV walk, unknown
  capability word ending the parse silently.
- NVM: LAR word and channel-flag count not checked against the regulatory section size
  (byte count compared with a channel count); PHY DB TXP group size not checked.
- HT rate table (ieee80211.c): MCS 10 HT40 192 -> 162, MCS 28 HT40 324 -> 648,
  MCS 28 HT40 SGI 520 -> 720 (500 kbit/s units). MCS 10 affects 2x2 cards at 40 MHz.

## net80211 change
- `ieee80211_parse_htinfo()` set the node's channel width from the channel flags alone. iwm
  (one channel entry per channel number) marks HT40-capable channels HT40U|HT40D, so every
  HT node looked 40 MHz wide. Width is now 40 only if the AP's HT info allows it.

## Locking rules (for reviewers)
- `sc_rwlock` (writer) > `sc_mtx`. Tasks other than init_task never take `sc_rwlock`.
- Never call net80211 functions that may transmit (`ieee80211_new_state`, `sc_newstate`,
  `ieee80211_input`, `ieee80211_end_scan`, `ieee80211_send_bar`) with `sc_mtx` held:
  `iwm_send()` takes it.
- `iwm_calib_stop()` and `iwm_led_blink_stop()` drop `sc_mtx` around `untimeout()`.
